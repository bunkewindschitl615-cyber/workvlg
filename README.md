# WORKVLG

Сайт строительной и ремонтной компании WORKVLG (Волгоград и Волгоградская область).

Стек: [Astro 7](https://docs.astro.build) + TypeScript (strict), Node-адаптер `@astrojs/node` в режиме `standalone`.
Страницы собираются в статический HTML; на Node-сервере выполняются только серверные маршруты (приём заявок — этап 7).

## Требования

- Node.js 26 LTS (минимум 22.23.4), npm 11+.

## Запуск

```powershell
npm install
Copy-Item .env.example .env   # затем заполнить значения
npm run dev                   # http://localhost:4321
```

| Команда | Назначение |
|---|---|
| `npm run dev` | Режим разработки с горячей перезагрузкой |
| `npm run check` | Проверка типов TypeScript и Astro-компонентов |
| `npm run build` | Проверка типов + production-сборка в `dist/` |
| `npm run preview` | Локальный просмотр production-сборки |
| `npm start` | Запуск production-сервера (`HOST`, `PORT` из окружения) |

## Конфигурация

Все настройки — в `.env` (образец с пояснениями: `.env.example`). Значения подставляются при сборке, поэтому после изменения `.env` нужно выполнить `npm run build` заново.

- **Контакты** (`PUBLIC_CONTACT_*`, `PUBLIC_*_URL`). Пустое значение — канал не показывается на сайте. Некорректный телефон или ссылка останавливают сборку с понятной ошибкой.
- **Instagram** выводится только при `PUBLIC_SHOW_INSTAGRAM=true` и всегда со сноской о статусе компании Meta в РФ.
- **Индексация** выключена по умолчанию (`PUBLIC_INDEXING=false`): `robots.txt` запрещает обход, на страницах стоит `noindex`. Включать только после наполнения сайта реальными данными.
- **`SITE_URL`** — публичный адрес сайта для canonical, sitemap и Open Graph.

Код конфигурации: `src/config/` (`site.ts` — общие данные, `contacts.ts` — каналы связи, `features.ts` — флаги функций).

## Структура

```
src/
  config/          site.ts, contacts.ts, features.ts, navigation.ts
  components/
    layout/        Header (с мобильным меню), Footer, MobileContactBar
    seo/           SeoHead — метатеги
    ui/            Button, Card, Section, Badge, Icon (+ icons.ts), Logo, PlaceholderNotice
  layouts/         BaseLayout (html/head), PageLayout (шапка, подвал, панель связи)
  pages/           index, 404, robots.txt, styleguide
  styles/          tokens.css — дизайн-токены, base.css — базовые стили
public/            статические файлы
```

## Дизайн-система

- Все цвета, размеры, отступы и анимации задаются переменными в `src/styles/tokens.css`. В компонентах литеральные значения не используются.
- Шрифт Onest (кириллица + латиница) скачивается при сборке и раздаётся с собственного сервера — первая сборка требует доступа в интернет.
- Образцы всех компонентов: `/styleguide/` (закрыта от индексации, не попадает в sitemap; перед запуском удалить или защитить).
- Материалы-заглушки помечаются компонентом `PlaceholderNotice`.

## Контент

- Направления работ: `src/content/services/*.md`. Группы работ — поле `groups`, его можно дополнять. Пока `ownerConfirmed: false`, на сайте стоит пометка «Черновик».
- `hasPage: true` создаёт страницу `/uslugi/<имя-файла>/`. Для неё обязательны `h1`, `seo`, `audience`, `benefits` и `groups` (или `tasks`). Текст страницы — в теле Markdown, подзаголовки `###`, ссылки на соседние услуги относительные (`../drugaya-usluga/`).
- Значения с двоеточием внутри текста в YAML нужно брать в кавычки.
- Тексты главной страницы: `src/data/home.ts`, шаги работы: `src/data/process.ts`.
- Вместо фотографий стоят заглушки `MediaPlaceholder` — заменяются на реальные фото через `<Image>` из `astro:assets`.

## Состояние

Этапы 1–4 завершены, плюс рабочая заявка через Telegram и публикация на GitHub Pages.

Заявка не хранится на сайте: форма проверяет поля и открывает чат Telegram с готовым текстом, отправляет сообщение сам посетитель. Фото прикрепляются уже в чате. Когда появится свой сервер, приём заявок можно переключить на него.

## Публикация на GitHub Pages

Сайт статический, поэтому работает без включённого ноутбука. В репозитории есть `.github/workflows/pages.yml`.

1. Создайте пустой репозиторий на GitHub и отправьте в него ветку `main`.
2. В репозитории: Settings → Pages → Build and deployment → Source: GitHub Actions.
3. Следующий push в `main` соберёт сайт и опубликует его. Адрес будет в разделе Actions и в Settings → Pages.

Пока включён `noindex`: поисковики не индексируют черновик на github.io. Свой сервер подключается позже и этот вариант не отменяет.
Ссылки меню ведут на ещё не созданные разделы и пока открывают страницу 404.
Каталоги `data/` и `uploads/` зарезервированы под базу заявок и фото клиентов и исключены из git.
